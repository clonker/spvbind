# Reproducers

One module per class of finding from the first runs of `differential.py` and `spvbind_fuzz` against SPIRV-Reflect at
commit `563dc9a` (2026-10-05, `main` at the time). Each is a `--corpus` seed for the mutate mode as well. Line numbers
refer to `spirv_reflect.c` at that commit. None reported upstream yet. `../patches/spirv-reflect-known-crashes.patch`
guards against the four crashes, so that fuzzing can go on past them.

| Module                                 | spirv-val | What SPIRV-Reflect does                                                                                                                                                                                                                                                                                                                                                                      |
|----------------------------------------|-----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `absolute_offset_overflow.spv`         | valid     | A nested member's `absolute_offset` is `offset + parent.absolute_offset` in `uint32_t` (`ParseDescriptorBlockVariableSizes`, line 2869), so an outer member at Offset 4294967256 puts the inner struct's members at 0, 4, 8, … instead of 4294967296, …; spvbind says 4294967296. Absurd for a push constant block, but valid SPIR-V, and the wrong number is reported rather than an error. |
| `recursive_struct_stack_overflow.spv`  | invalid   | `%8 = OpTypeStruct %8`, one word changed by the mutator: `ParseType` recurses into the member types without a depth limit and overflows the stack (SEGV). Invalid SPIR-V, but a crash on one flipped word.                                                                                                                                                                                   |
| `cleanup_null_interface_variables.spv` | invalid   | A module truncated to 63 words: the parse fails, and `spvReflectDestroyShaderModule` (line 5116) frees `p_entry->interface_variables[j]` for a count of variables that were never allocated: SEGV. Known from the earlier C++ fuzzing (finding 3 in `docs/fuzzing.md` of branch `old`).                                                                                                      |
| `cleanup_null_functions.spv`           | invalid   | A module whose last instruction is cut short: `DestroyParser` (line 700) frees `p_parser->functions[i].parameters` with `functions` still null and `function_count` set: SEGV. Likewise for `access_chains` (line 708).                                                                                                                                                                      |
| `source_continued_without_source.spv`   | invalid   | An `OpSourceContinued` without an `OpSource` carrying text before it: `ParseNodes` (line 851) calls `strlen` on the null `source_embedded`: SEGV. Found by the FuzzTest bytes target.                                                                                                |
| `member_index_allocation.spv`           | invalid   | An `OpMemberName` whose member index is a mutated word: `ParseMemberCounts` (line 1488) sizes the struct's member arrays by the largest index named, here about 190 GB, and only a failed `calloc` stops it (`ALLOC_FAILED`). Known from the earlier C++ fuzzing (finding 2 there); under AddressSanitizer it needs `allocator_may_return_null=1`, which `spvbind_fuzz` sets. |
| `member_index_quadratic_hang.spv`       | invalid   | An `OpMemberName` with member index 2097152: the allocation succeeds this time, and `ParseDescriptorBlockVariableSizes` (line 3016) then orders the members by offset in a loop quadratic in their count, so a module of 1.5 KB takes hours. Found by the FuzzTest bytes target with `--time_limit_per_input`. |
| `heap_buffer_overflow.spv`              | invalid   | **Heap buffer overflow, a write**: `ParseNodes` counts functions as it walks function bodies (line 1121) and `ParseFunctions` allocates that many (line 1409), but then fills one per `OpFunction` node in the module (lines 1420 to 1431), so a stray `OpFunction` (here one word of a function body mutated into it) writes a second function's `id` past the array (`ParseFunction`, line 1244). Found by the FuzzTest bytes target after the other classes were patched; not in the patch. |

```sh
cmake --build fuzz/build && for f in fuzz/reproducers/*.spv; do fuzz/build/reflect_dump $f; echo "exit $?"; done
```
